# مِهنتي — منصة توظيف مستقلة

منصة عربية RTL تربط العمال بأصحاب الأفران والمخابز والمطاعم.

## التقنية
- React 19 + Vite 6
- Supabase Auth + PostgreSQL + RLS + Realtime
- Netlify للنشر

## قاعدة البيانات — مهم
المشروع المرتبط حالياً هو Supabase **Mihnaty**. كان يحتوي على مخطط سابق مختلف (26 جدولاً)؛ لذلك لم نحذف أو نعدّل تلك الجداول. أُنشئ مخطط مستقل بأسماء `mihnati_*` لتشغيل هذه المنصة دون تعارض أو فقد بيانات.

المخطط الحالي:
- `mihnati_profiles`: ملفات العمال والحسابات التجارية.
- `mihnati_jobs`: إعلانات الوظائف.
- `mihnati_bookings`: الحجز وموافقتا الطرفين والإلغاء.
- `mihnati_messages`: الدردشة.

الملف المرجعي الموحد: `supabase/migrations/20261108195700_mihnati_platform.sql`.

**لا تشغّل ملفات SQL القديمة أو تعِد إنشاء جداول `profiles/jobs/bookings/messages` العامة.** تم استبدالها بملف الهجرة أعلاه. المخطط المطبق بالفعل على مشروع Supabase يتضمن كذلك هجرات الحماية وفهارس المفاتيح الخارجية.

## إعداد محلي
1. ثبّت Node.js 20 أو أحدث.
2. نفّذ `npm install`.
3. أنشئ ملف `.env` اعتماداً على `.env.example`.
4. أضف عنوان Supabase ومفتاح publishable (أو anon القديم للتوافق) في:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
5. نفّذ `npm run dev` للتشغيل و`npm run build` للبناء.

لا تستخدم `service_role` أو أي مفتاح سري داخل الواجهة أو متغير يبدأ بـ `VITE_`.

## إعداد Netlify
- Build command: `npm run build`
- Publish directory: `dist`
- أضف المتغيرين `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` إلى Site configuration → Environment variables.
- نفّذ Deploy جديد بعد حفظ المتغيرات.
- إعداد SPA redirect موجود في `netlify.toml`.

## الوظائف المنفذة
- تسجيل ودخول بالبريد وكلمة المرور، وحساب عامل أو حساب تجاري. تمت مواءمة Auth trigger القديم ليحوّل business إلى employer في جدول النظام السابق مع إنشاء ملف MIHNATI منفصل.
- نشاطات: فرن، مخبز، مطعم، مع قائمة تخصصات لكل نشاط.
- نشر الوظائف وتصفحها.
- حجز ذري يمنع وجود أكثر من حجز نشط للوظيفة نفسها.
- لا يستطيع العامل حجز وظيفته، ولا يستطيع الحساب التجاري الحجز كعامل.
- موافقة مستقلة من العامل وصاحب العمل؛ لا يتم الاتفاق إلا بموافقتهما.
- إلغاء الحجز المعلّق من أحد الطرفين يعيد الإعلان إلى متاح.
- دردشة بين طرفي الحجز النشط فقط مع Realtime.\n- فتح اتجاهات الوصول إلى موقع العمل عبر خرائط Google.\n- تسجيل وصول العامل بعد الاتفاق، مع إشعار Telegram عند الحجز وعند تسجيل الوصول عبر Edge Function.
- تعليمات تحويل يدوي خارج التطبيق فقط؛ لا محفظة ولا إيداع ولا سحب ولا تحقق دفع.

## ما لم يكتمل بعد
- الخرائط وتحديد الموقع ومسار الوصول الفعلي.
- إشعار Telegram يذهب حصراً إلى المحادثة الخاصة المحددة في إعداد الوظيفة، وعند تأكيد وصول العامل فقط. نص الإشعار: رقم الهاتف، اسم العامل، و«لقد وصل إلى [المخبز/الفرن/المطعم]: [الاسم]».\n- يلزم إضافة `TELEGRAM_BOT_TOKEN` كسرّ في Supabase → Edge Functions → Secrets. لا تضع التوكن في GitHub أو الواجهة. يجب إلغاء التوكن الذي كُشف في المحادثة وإصدار توكن جديد من BotFather قبل تفعيله.
- لوحة إدارة ومراجعة البلاغات.
- اختبار قبول شامل بحسابي عامل وصاحب عمل حقيقيين، ونشر Netlify النهائي.
- تدفق آمن للتحقق من الهوية. لا تجمع الرقم الوطني أو صور المستندات في النسخة الحالية.
